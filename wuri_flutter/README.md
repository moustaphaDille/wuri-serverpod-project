# Wuri Flutter

Wuri's mobile and Web application. This application provides the project's
user interface and communicates with the Wuri server through the Serverpod
client generated in `../wuri_client`.

## Main features

- Email registration, sign-in, and password reset;
- Client or partner profile selection;
- Space search with filters and map display;
- Client favorites, bookings, payments, and notifications;
- Partner space management and booking request management;
- Admin user management and partner application review;
- Responsive interface for mobile, tablet, and Web browsers;
- French and English localization.

## Architecture

| Directory | Purpose |
| --- | --- |
| `lib/app` | GoRouter routes and navigation |
| `lib/providers` | Application state and endpoint calls |
| `lib/screens` | Client, partner, admin, and authentication screens |
| `lib/widgets` | Reusable components and responsive layouts |
| `lib/theme` | Colors, typography, and Material theme |
| `lib/l10n` | French and English translations |
| `assets/config.json` | Local API URL configuration |

The code in `../wuri_client` is generated by Serverpod. Do not edit it
manually: server endpoints and models regenerate this package.

## Requirements

- Flutter and Dart versions compatible with `pubspec.yaml`;
- The Wuri server package installed and working;
- A running Wuri server for API calls.

## Installation

From the project root:

```powershell
flutter pub get
```

The Dart workspace can also resolve dependencies from the project root:

```powershell
dart pub get
```

## Local development

The recommended command starts the server and the Flutter application:

```powershell
cd ..
serverpod start
```

To run only the Flutter application while the server is already running:

```powershell
flutter run
```

To test the Web application:

```powershell
flutter run -d chrome
```

The default local server URL is `http://localhost:8080`. The
`assets/config.json` file is used for local configuration. In production, the
API URL must point to the production server.

## Builds

Web build:

```powershell
flutter build web
```

Android build:

```powershell
flutter build apk
```

Before a production build, verify the API URL, authentication mode, target
platform permissions, and server secret configuration.

## Tests and verification

```powershell
dart analyze
flutter test
```

Test the interface with a wide Web window, a resized window, and a mobile
screen. Pages must avoid horizontal overflow and remain readable at all
available widths.

## Important rules

- Never put passwords, tokens, or private keys in the Flutter application;
- Never edit generated code in `../wuri_client`;
- Business operations must use the existing providers and Serverpod
  endpoints;
- Add every new user-visible string to the localization files;
- New pages must use the existing responsive components and constraints.
